## 3. Testbed Isolation Level for Step 07 *(Approved: L1)*

- **Decision Status:** **APPROVED — L1** (user approval: `L1 isolation ok, approved step 00`, 2026-11-05). The optional Mixed L1 + L3 Kali attachment remains optional and will be revisited at the Step 07 design checkpoint.

### Hardware Constraint Summary
- CPU (`i7-12700H`, 14C/20T) and Disk (`475.4 GB` free on `D:\`) are abundant.
- **RAM is the binding constraint:** Total host RAM is `15.67 GB`, with `~3.66 GB` free during normal Windows 11 desktop + IDE usage (expandable to `~7–8 GB` free by closing heavy Windows apps).

### Comparison of Isolation Levels on This Machine

| Option | Architecture | Estimated VM RAM Needed | Feasibility on 15.67 GB Host |
|---|---|---|---|
| **L1 (Recommended Primary)** | One **Ubuntu 22.04 LTS Server VM** (`4–5 GB RAM`, 4 vCPUs, no GUI); each tenant runs as isolated Mininet network namespaces with its own OVS bridge and dedicated RYU controller process | `4–5 GB` | **High (Safe & Reliable)** |
| **Mixed L1 + L3 (Optional Showcase)** | Ubuntu 22.04 Server VM (`4 GB RAM`) running the 3-tenant OVS/RYU topology + existing **Kali Linux VM** (`2–3 GB RAM`) attached over an isolated VMware Host-Only `VMnet` to Tenant 1's OVS bridge for real-VM attack validation | `6–7 GB` (requires closing browsers/heavy apps on Windows) | **Moderate (Feasible for Step 07/08 demo runs)** |
| **Pure L3** | 3 tenants × 3 real VMs (attacker, benign, victim) = 9 VMs + controller VM | `18–24 GB` | **Infeasible on 15.67 GB RAM** |

### Recommendation
Approve **L1** inside a single **Ubuntu 22.04 LTS Server VM (4 GB RAM, 4 vCPUs)** as the guaranteed baseline for all 3 tenants in Step 07/08, with an optional **Mixed L3 attachment** of the existing Kali Linux VM for Tenant 1 if host free RAM allows (`>= 7 GB` free before VM boot), stating the exact setup transparently in the thesis.
