# Experiment Specification (shared definitions)

All steps use these definitions. Changing any of them requires explicit user approval and an entry in `docs/DEVIATIONS.md`.

## 1. Tenants

- Testbed: 3 tenants with different traffic profiles (for example Finance, Healthcare, Education).
- Simulation: N in {3, 5, 10}. The default for poisoning sweeps is N = 10, because with N = 3 one malicious tenant is already 33%.

## 2. Data partitioning (non-IID)

- Natural partition: assign attack families and benign traffic to tenants by profile (for example one tenant is DoS/DDoS-heavy, another brute-force-heavy).
- Dirichlet partition over class labels with alpha in {0.1, 0.5, 1.0} and an IID control. Default alpha = 0.5.
- Per tenant split: 70% train, 10% validation, 20% test, stratified, fixed seed. A global held-out test set (never seen by any tenant) is also kept.
- Splitting is done before any scaling or feature selection statistics are computed.

## 3. Model

- Default local model: GRU over the selected top-k feature vector (sequence layout decided in Step 02).
- Comparison models in Step 02: DNN (MLP) and LSTM.
- Selection rule: choose the model with the best macro-F1 per parameter count; the GRU stays the default if it is within 0.5 F1 points of the best.

## 4. Federated training defaults (configurable)

- Rounds: 30. Local epochs: 3. Batch size: 128. Optimizer: Adam, learning rate 1e-3.
- Aggregation weight: proportional to local sample count for FedAvg.
- Client participation: all tenants every round (a partial-participation study is optional).

## 5. Aggregators

1. FedAvg (baseline)
2. Static-weight aggregation (re-implementation of the fixed-weight idea of Ali et al., 2023; weights chosen by grid search on validation data and then frozen)
3. Coordinate-wise trimmed mean (trim fraction beta in {0.1, 0.2})
4. Cosine-similarity clustering filter (largest cluster is aggregated)
5. Optional: Krum / Multi-Krum, coordinate-wise median

## 6. Attacks (applied to a fraction of tenants)

| Attack | Definition |
|---|---|
| Label flipping | Flip a fraction of attack labels to benign (and optionally the reverse) in the malicious tenant's local training data |
| Backdoor / model replacement | Stamp a trigger pattern on a fixed subset of features and relabel to benign; optionally scale the update to dominate the aggregate |
| Update scaling | Multiply the honest update by a factor (default 10) or flip its sign |

Poisoned tenant fraction: 0%, 10%, 20%, 30% (N = 10: 0, 1, 2, 3 tenants). Report the backdoor attack success rate separately from clean accuracy.

## 7. Privacy

- Gaussian mechanism with L2 clipping norm C.
- Privacy accounting with a standard accountant (RDP / moments accountant). Report epsilon and delta for every run.
- Adaptive policy from the poster: epsilon_i = epsilon_total * (1 / s_i) / (sum_j 1 / s_j), where s_i is the tenant sensitivity score (higher sensitivity means a smaller epsilon, so stronger protection).
- Required comparison: uniform epsilon versus adaptive epsilon at equal total budget.
- Epsilon sweep: {0.5, 1, 2, 4, 8, infinity (no DP)}.
- Privacy attack: membership inference (loss-threshold attack as the minimum; shadow-model attack optional). Report attack accuracy and AUC.

## 8. Verification

- Threat model: the aggregator may be lazy or malicious (it can drop, replace, or alter updates or the aggregate) and is also honest-but-curious about individual updates.
- Required tamper tests: modified aggregate, dropped tenant, replayed old update, substituted update. Report the detection rate (target: all detected) and the false-alarm rate (target: zero on honest runs).
- Report overhead of masking, commitments, and verification separately.

## 9. Metrics

- Detection: accuracy, precision, recall, F1 (macro and attack-class), attack detection rate (recall on attack traffic), false positive rate, ROC-AUC.
- Robustness: clean accuracy under attack, accuracy drop versus the 0% poisoning run, backdoor attack success rate.
- Privacy: epsilon, delta, membership-inference accuracy and AUC.
- Efficiency: bytes per round per tenant, ratio versus FedAvg, wall-clock time per round split into local training, DP, masking and commitment, upload, aggregation, verification, download, deployment.
- Live testbed: detection latency per flow, time from attack start to mitigation rule installation, false mitigations of benign traffic.

## 10. Statistics and reporting

- Seeds: {0, 1, 2, 3, 4} minimum. Report mean and standard deviation. Use paired tests (Wilcoxon signed-rank) for key comparisons and say how many seeds were used.
- Every experiment has a config file under `configs/experiments/` and writes `results/<experiment_name>/summary.json` plus per-round CSV logs.
- Figures are generated by scripts only (never edited by hand). Tables are generated as LaTeX by script.

## 11. Ablation ladder (Step 09)

1. FedAvg
2. FedAvg + adaptive DP
3. FedAvg + adaptive DP + robust aggregation
4. FedAvg + adaptive DP + robust aggregation + verifiable secure aggregation
5. Full TrustFed-SDN (all components, on the live testbed)

Each rung is evaluated clean and under each attack, with the same seeds.

## 12. Naming

- Python packages and files: `snake_case`. Config names: `<topic>_<variant>.yaml`. Result folders: `results/<step>_<experiment>_<date>/`.

## 13. Paper-Ready Experiment Logging (`docs/EXPERIMENT_RESULTS_LOG.md`)

After every experiment run or step completion, the agent MUST log all numerical findings in Markdown format inside `docs/EXPERIMENT_RESULTS_LOG.md`.
The logged records must include:
- Experiment identifier, Date/Timestamp, and Git commit hash
- Dataset and partition settings (e.g., InSDN, Dirichlet alpha=0.5)
- Model architecture and hyperparameter summary
- Detection performance table: Mean ± Std for Accuracy, Precision, Recall, Macro-F1, Attack Detection Rate, False Positive Rate (FPR), ROC-AUC
- Security & Privacy metrics: Backdoor Attack Success Rate (ASR), Privacy budget (epsilon, delta), Membership Inference Attack (MIA) Accuracy
- System overhead table: Local training time (s), Masking & Commitment time (ms), Aggregation time (ms), Verification time (ms), Communication cost per round (KB/MB)
- Path to raw artifact (`results/<step>_<experiment>/summary.json`)

This ensures that writing the thesis document and research paper requires zero re-calculation or log digging.
